Programmable World Model, from Alaya Lab, with Zheng-Hui Huang, Guixu Lin, and Jiacheng Lin as the leading authors. The pitch is that video world models can generate convincing interactive scenes but have no idea what is actually happening in them. A door that opens in frame does not update any state. A character that falls gets back up because the model never tracked that it fell. This paper separates the problem into two halves: an explicit, programmable world state that a rules engine maintains, and a generative video model that renders what the state says should be visible.

The starting observation is that today's interactive video models are prompted, not programmed. You can say "make the door open" and get a plausible clip, but there is no persistent rule governing when the door opens, what happens if you touch it twice, or whether it is still open when the camera pans away and comes back. The model has no memory of off-screen entities, no inventory, no task progress. For a multiplayer game engine or any long-horizon interactive experience, that is a dealbreaker. The authors argue you need a representation that is compact enough for a program to read and write, and structured enough to drive pixel-level visual generation.

Their answer is the state-augmented 3D oriented bounding box. Every entity in the world is a 3D box with position, extent, and orientation in a shared coordinate system, augmented with persistent identity, semantic category, dynamic state, and appearance. No meshes, no skeletons, no pre-baked animations. A coding agent, a VLM acting as a programmer, takes a reference image plus a natural-language description and writes executable code: a state schema defining entities, and event rules like "on hit, subtract damage from health; when health reaches zero, set status to down; when all enemies are down, the player wins." A lightweight engine executes that code. When you fire a shot, the engine updates the target's health, and if it hits zero, the entity's status flips and it stays down for the rest of the scene.

The bridge between state and pixels is a deterministic compiler. It projects the evolving 3D boxes along the target camera trajectory and rasterizes them into pixel-aligned, spatio-temporal control signals. Those signals tell the pretrained video model where each entity is, which way it faces, and what state it is in. The video model fills in everything the boxes do not specify: fine geometry, texture, limb articulation, secondary motion. The split is clean. The rules engine guarantees consistency, and the video model guarantees it looks real.

Why oriented boxes rather than a full scene graph? The paper argues the representation has to survive a specific failure mode of generative rendering: the model can only synthesize what is in frame, so anything that leaves the camera vanishes from the visual context. If state lives only in the pixels, off-screen entities are gone. By keeping state in the box world, independent of what is rendered, the engine preserves identity, position, and health for entities the camera is not currently looking at. When the camera pans back, the compiler re-projects those preserved boxes and the renderer brings them back consistently. That is the mechanism behind the off-screen entity results, and it is the property no pure video world model can offer without an explicit state store.

They built Combat State Bench to test this: 50 clips of combat scenarios where entities start off-screen, take hits, die, and stay dead. The benchmark reconstructs the initial 3D layout from the first frame, lets an AI agent evolve a combat scenario under the game rules, and an automatic verifier checks box geometry, ground contact, temporal continuity, and that state transitions persist. The numbers are the story. Their method scores 94 percent count accuracy and 98 percent state accuracy. The two interactive video world models they compare against, LingBot World V2 and YUME, score 40.75 and 32 percent count accuracy, and 8 and 58 percent state accuracy. State accuracy is where the gap is most dramatic: LingBot World V2 tracks only 8 out of 50 death events correctly, meaning it essentially forgets that things died.

The representation choice is where the real design argument lives, and the paper is careful about it. They lay out a spectrum. Free text is easy to write but imposes no geometric constraint on the renderer. 2D boxes and masks give image-space control but are locked to a particular camera view. Full 3D scenes or dense rendering buffers like G-buffers give the finest control but demand heavy supervision and expensive inference-time reconstruction. There is also a train-test mismatch problem that is easy to overlook: training representations are extracted from observed video, so the model learns to render from boxes it saw in the data. At inference, the program must construct box trajectories from desired state changes, which may look nothing like the extracted trajectories. A 3D oriented bounding box sits at a sweet spot: compact, editable by code, with enough spatial structure to drive generation, while the video model handles the detailed motion the boxes leave unspecified.

Training the renderer requires a data curation pipeline that recovers the supervision the interface needs. Given real video, the system reconstructs the 3D boxes, semantic attributes, and camera parameters, then pairs them with the rendered control signals, so the model learns to follow the box-based conditioning and synthesize the rest. That is standard enough, but the point is that the renderer never has to learn the game rules. Rules are the program's job. The renderer just learns a mapping: given these pixel-aligned controls and this camera path, produce the frame. That separation is what makes the system composable. You can write a new game in code, define its entities and event triggers, and the same renderer handles it without any further training, because the renderer's contract is the control signal, not the semantics of any particular game.

The qualitative results reinforce the numbers. Under a large camera rotation, the model keeps the scene coherent and reveals characters that were behind the camera, following the persistent state rather than re-inventing the scene from the current frame. In a novel minotaur scene with a dynamic camera, entity identities and states hold across the clip. When a death event fires, the target transitions to its downed state and remains there in every subsequent frame, while the rest of the scene keeps evolving. The failure mode you would expect, a dead entity reappearing because the model lost track of it, is exactly what the 98 percent state accuracy says does not happen.

It is worth separating what this benchmark actually measures from what people might assume it measures. Combat State Bench is a state-consistency test, not a visual-quality test. The clips are judged on whether the box geometry, ground contact, and entity states track correctly over time; the renderer's job is to make those states look real. So a high state score means the architecture preserves information that a pure video model cannot, not that the pixels are the most photorealistic available. The 94 percent count accuracy, by contrast, is closer to a capability claim: the system reliably places and keeps the right number of entities in the scene even as the camera moves and events fire. That is the harder number to fake, because it requires the engine and the compiler to agree about where every box is at every timestep.

There are honest limits. The world is as rich as the boxes plus whatever the video model can plausibly invent. Fine-grained physics, object permanence for tiny items, and non-rigid deformation are still the renderer's guess, not the engine's guarantee. The benchmark is deliberately controlled, 50 clips in a combat setting, so generalizing to open-ended, creative, or social worlds is not yet demonstrated. And the coding-agent step is a real dependency: if the VLM writes a buggy state program, the engine will faithfully execute the bug. The system trades a flexible-but-amnesic generator for a precise-but-programmable one, and the trade pays off dramatically on state consistency. As world models move toward being actual interactive engines rather than impressive video clips, this explicit-state-plus-renderer split looks like the architecture that makes persistence, programmability, and visual quality compatible instead of competing.
